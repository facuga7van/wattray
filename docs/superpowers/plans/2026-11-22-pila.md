# pila Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ícono de bandeja por periférico con su % de batería, Win32 nativo, ~1 MB de RAM.

**Architecture:** Un `.exe` Rust (`windows_subsystem = "windows"`). Hilo UI: ventana oculta top-level + íconos. Hilo worker: lee todos los lectores, manda `Vec<Reading>` al UI con `PostMessageW`, duerme con `thread::park_timeout(120 s)`; el UI lo despierta (`unpark`) ante `WM_DEVICECHANGE`. Los timeouts HID nunca bloquean la bandeja.

**Tech Stack:** Rust stable (MSVC), única dependencia `windows-sys`. CRT estático para que el exe no pida redistributable.

**Spec:** `docs/superpowers/specs/2026-11-22-pila-design.md`

> Nota: el plan lleva interfaces, datos de protocolo y verificación; el código se escribe en la ejecución (misma sesión), no se duplica acá.

## Datos de protocolo

### HID (convención)
- `ReadFile` en Windows siempre trae el report id en byte 0. Para usar offsets estilo hidapi (SteelSeries): si `buf[0] == 0` se descarta ese byte.
- `WriteFile` exige exactamente `OutputReportByteLength` bytes: pedido + padding con ceros. Byte 0 = report id.
- Open con `FILE_SHARE_READ | FILE_SHARE_WRITE`, `FILE_FLAG_OVERLAPPED`; se abre y cierra en cada poll (sin reportes viejos en buffer).

### Logitech HID++ 2.0
- Interfaces: VID `046D`, usage page `0xFF00` o `0xFF43`, `OutputReportByteLength == 20` (reporte long `0x11`).
- Pedido: `[0x11, dev, feat_idx, (func << 4) | SW, params…]`, `SW = 0x0A`. Respuesta válida: mismos 4 primeros bytes. Error 2.0: `buf[2] == 0xFF && buf[3] == feat_idx`. Timeout 250 ms (los slots vacíos responden error 1.0 por la colección short, que no abrimos → timeout).
- `dev` probados: `0xFF` (directo) y `1..=6` (slots de receptor).
- Root (idx 0) func 0 `getFeature(id_hi, id_lo)` → `params[0]` = índice (0 = no está).
- `0x1004` Unified Battery, func 1 → `[soc%, level_flags, charging(1|2=cargando, 3=lleno), ext_power]`. Si `soc == 0`: flags `8→100, 4→50, 2→20, 1→5`.
- `0x1000` Battery Status, func 0 → `[nivel%, next, status(1..=4 cargando/lleno)]`.
- `0x1001` Battery Voltage, func 0 → `[mV_hi, mV_lo, flags(bit7 = cargando)]`; curva mV→%: 4186/100, 4067/90, 3989/80, 3922/70, 3859/60, 3811/50, 3778/40, 3751/30, 3717/20, 3671/10, 3646/5, 3579/2, 3500/0 (interpolación lineal).
- `0x0005` Device Name: func 0 → `params[0]` = largo; func 1 `(offset)` → hasta 16 chars.

### Razer
- VID `1532`, cualquier interfaz con `FeatureReportByteLength == 91`.
- Reporte de 90 bytes (+ report id 0 adelante): `[status=0, tid, 0,0, 0, size=0x02, class=0x07, id, args[80], crc, 0]`; `crc` = XOR de bytes 2..88 del reporte de 90.
- `HidD_SetFeature`, esperar, `HidD_GetFeature` (hasta 5 intentos cada 15 ms mientras `status == 0x01` busy). Éxito: `status == 0x02`.
- Batería: id `0x80` → `args[1]` 0–255 → %. Cargando: id `0x84` → `args[1] == 1`.
- `tid` probados en orden: `0x1F, 0x3F, 0xFF, 0x9F`; se queda con el primero que da éxito.
- Sin hardware para probar: queda "según referencia".

### Bluetooth
- `SetupDiGetClassDevsW` con enumerador `BTHLE` y `BTHENUM`, `DIGCF_ALLCLASSES | DIGCF_PRESENT`; instance id `…\DEV_*`.
- Batería: `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2` (BYTE). Conectado: `{83DA6326-97A6-4088-9453-A1923F573B29} 15` (BOOLEAN, verificado en esta PC). Nombre: `DEVPKEY_Device_FriendlyName`.
